Version semantics
  fix:   patch  (1.0.0 → 1.0.1) — Bug fixes
  feat:  minor  (1.0.0 → 1.1.0) — New features
  feat!: major  (1.0.0 → 2.0.0) — Breaking changes

Format: <type>: <previous_version> → <new_version> — <summary>, then Fixed / Added / Changed / Impact (only the relevant sections).
New entries go at the top, below this legend.

fix: 38.4.2 → 38.4.3 — Android Back button goes back one screen instead of closing the app

Fixed
- Android app (Capacitor wrapper): before → the hardware Back button closed the app from Settings, an open note or editing; after → it closes the menu, a sheet or search, goes from editing back to viewing, closes the note, leaves a folder or Settings, and exits only from the plain home screen.
- How: notes-app.js registers a Capacitor `backButton` listener (needs @capacitor/app). It calls history.back(); if the WebView has no history entry to go back to, the same step is applied directly. The popstate handler's logic moved into applyBack(). Browsers are unaffected.

Changed
- Android build (android-apk branch): adds the @capacitor/app dependency, takes the web files from master during the build, and uses a proper adaptive launcher icon (paper-coloured background plus the logo) instead of the plain resized image.
- Settings → About shows 38.4.3.

Impact

fix: 38.3.0 → 38.3.1 — Caret no longer jumps above the list after Backspace

Fixed
- Enter at the end of a list, Backspace on the empty item, then typing: before → on a phone the letters appeared on a new line above the list (the caret was on the list block or at the start of the note, not inside the last item); after → typing continues at the end of the list item.
- How: rich-text-editor.js tracks the last caret inside a line (lastGood) and, when the next insert or composition starts with the caret on the note, on a bare list block, or after a delete, moves it back into that line (stray()). It is skipped after a deliberate tap, touch or arrow/Home/End/Page key.

Added

Impact
- Typing after deleting a list item stays in the list. Not reproduced with a real phone keyboard, so this is a safeguard; a new video would help if it still happens.

Impact
